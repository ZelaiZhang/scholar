# 解读实验结果

## 输入

- 读取 `05-experiment-design.md`、外部实验结果、数据版本与代码提交标识。
- 不接收包含可识别健康信息的病例级结果。

## 流程

1. 核对结果来源、实验版本、样本量、运行次数和预设假设。
2. 区分主要结果、探索性结果、最佳单次运行和完整分布。
3. 检查统计意义、效应大小、置信区间、实际意义和多重比较。
4. 查找异常、选择性报告、数据泄漏、缺少对照和与设计不一致之处。
5. 分别写出“可以支持”“暂不能支持”和“需要补充”的结论。
6. 更新 `06-result-analysis.md`，把新事实关联到外部结果文件而非虚构论文来源；保留既有人工文字，不覆盖人工解释。
7. 先运行 `research-os guide --project <slug> --workspace .`；只有命令成功且结果输入未报错，才读取已校验的 `artifacts/results-manifest.yaml`。逐项核对每个当前直接文件的 `path`、`sha256`、来源仓库和生成时间，不调用私有 Python API。
8. 删除 `06-result-analysis.md` 中全部过期、未知或重复的结果绑定。对清单中每个当前结果文件，逐字复制文件名和 64 位小写哈希，各写一次精确隐藏行：

```markdown
<!-- research-os:result-input name=<清单中的直接文件名>; sha256=<清单中的 64 位小写哈希> -->
```

   上述围栏代码块只展示语法，不会成为有效绑定。实际绑定必须各自写成顶层独立行，逐字匹配该格式，且不能放在围栏代码块、缩进代码块或普通 HTML 注释中；行前后不得附加空格、引用符号或其他文字。
9. 不得自行计算来替代清单校验，不得猜测或改写清单值；不得编造 marker、文件名或 sha256。只有质量门禁全部通过、每个当前输入已完成保守人工解释、绑定集合与当前清单完全一致且人工文字已保留后，才在所有绑定之后写入唯一一个顶层独立行 `<!-- research-os:stage=result-complete -->`；完成标记也不能位于围栏代码块、缩进代码块或普通 HTML 注释中。否则移除完成标记。再次运行 `guide`，确认“结果解读”为已产出；若仍为进行中，按提示修复绑定，不伪造 marker 或哈希。

## 质量门禁

- 禁止编造缺失的运行、显著性、误差条或失败原因。
- 不把相关性写成因果关系，不把小幅技术提升写成临床获益。
- 发现可识别健康信息时停止，不复制到报告。
- 保留人工解释和负结果，不能只挑选有利数据。
