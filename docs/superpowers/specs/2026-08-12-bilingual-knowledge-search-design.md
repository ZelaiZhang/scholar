# Research OS 中英双语知识检索设计

> 日期：2026-08-12；目标版本：v0.4.1；状态：沿用已批准的 v0.4 确定性知识库边界并开始实施。

## 1. 问题

当前 `kb search` 对英文标题和英文别名有效，但中文研究者最自然的查询会失败。真实基线中，`诊断准确性`、`思维链`、`微调量化` 均返回空结果。根因有两层：

1. 种子库别名几乎全是英文；
2. 当前 tokenizer 把连续中文视为一个完整 token，不能让较短查询匹配较长中文方法词。

这会迫使用户记忆英文术语，削弱知识库作为日常科研入口的价值。

## 2. 方案比较

### 2.1 外部模型翻译查询

召回灵活，但引入联网、费用、隐私授权、模型版本和非确定性，违反 v0.4 默认离线边界，不采用。

### 2.2 仅补人工中文别名

精度高、易解释，但用户输入 `诊断` 时仍不能稳定命中 `诊断准确性`，维护成本会随表达变体快速增加。

### 2.3 Unicode 规范化、CJK 二元词片与人工双语别名（采用）

使用 Unicode NFKC 和 `casefold` 统一全半角与大小写；拉丁文字继续按词切分；连续 CJK 文本同时产生完整片段与重叠二元词片。专业同义词由受审计的 `aliases.yaml` 明确维护。该方案本地、确定、可解释，不引入新依赖。

## 3. 行为设计

### 3.1 Token 规范化

- 先执行 NFKC，再执行 `casefold`。
- 拉丁字母和数字按现有单词边界切分。
- 连续 CJK 片段长度为 1 时保留单字；长度大于 1 时产生完整片段和所有重叠二元片段。
- 不生成 CJK 单字全集，避免 `医`、`模` 等高频字符造成大面积误召回。
- 空查询仍允许与结构化过滤条件配合；空查询且无过滤时保持当前返回全部 active 条目的行为。

示例：

```text
诊断准确性 -> 诊断准确性, 诊断, 断准, 准确, 确性
思维链     -> 思维链, 思维, 维链
QLoRA      -> qlora
```

### 3.2 双语别名

为 28 条种子目录补充经过人工选择的中文别名，至少覆盖：

- AI 科研自动化、AI 科学家、假设生成；
- 医疗大模型、鉴别诊断、对话诊断、诊断准确性；
- 思维链、自洽性、过程监督、检索增强生成；
- 低秩微调、量化微调、偏好优化、强化学习、人类反馈；
- 后训练量化、权重量化、八比特量化；
- 预测模型报告、偏倚风险、医疗影像报告、临床试验报告与方案。

别名是检索辅助，不是论文事实，不能进入项目证据账本。

### 3.3 排序与解释

- 保持 title 8、alias 6、topic 5、method 4、stage 3、heading 2、body 1 的既有权重。
- 同一字段内，查询 token 与字段 token 的交集按唯一 token 计分，避免重复堆叠。
- 输出继续报告命中的字段；中文别名命中显示为 `alias`。
- 同分规则、历史版本过滤和核验范围过滤完全不变。

## 4. 安全与兼容

- 默认不联网、不外发、不调用翻译模型。
- 不改变 catalog/card/project schema。
- 不自动关联任何全局来源到项目。
- 不引入拼音、embedding 或模糊编辑距离，以控制误召回和复杂度。
- 英文现有结果顺序必须由回归测试保持。

## 5. 验收

1. `诊断准确性` 首屏包含 STARD-AI；
2. `思维链` 能返回 CoT、自洽性或 ReAct 相关来源；
3. `微调量化` 能返回 QLoRA，且命中解释包含 alias；
4. 英文 `calibration` 的既有权重测试保持不变；
5. 相同知识库和参数重复运行得到字节等价 JSON；
6. 全量测试、warnings-as-errors、compileall、pip check、diff check、`kb doctor` 和安装 wheel 旅程通过。

## 6. 后续维护视图

双语检索完成后，在同一版本增加只读 `kb gaps`：确定性列出缺卡、仅摘要、未核验、`watch` 和超过 365 天未复核的条目，为把 17 张卡逐步扩展到 100 张提供行动队列。该命令不得联网、写 catalog 或自动升级核验状态。
