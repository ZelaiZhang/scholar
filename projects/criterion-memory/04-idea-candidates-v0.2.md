## 3. 候选科学问题：信息不完整时的承诺与复检

hypothesis HR01：

**在相同已观察证据下，早期节点判断与树路径承诺是否引起额外错误？将现有证据重新独立计算，能否消除这部分差异？**

这里关注证据到来后旧决策怎样影响当前判断。JSON 只是已有表示方式；原树是否确有路径依赖，必须先用代码审核与对照证实。

hypothesis HR02：

**在相同累计计算资源下，按证据变化选择复检时机，是否比固定时机复检或普通全历史重算更有效？**

候选贡献包括：可复核的路径依赖分析；区分整理、重算与撤销的受控评估；仅在数据支持时提出选择性复检策略。算法不能仅依赖未经校准的模型自报信心。

**多轮诊断中的自适应复检：判断修订与计算成本权衡**

## 4. 先证明机制，不急着增加算法

hypothesis / proposed protocol：

1. 固定对话回放。每个比较条件得到同一已观察前缀、知识与冻结判断模型，不能预先给完整病例或未来回答。
2. 对齐信息。分别构造原 JSON 历史、无损文本整合包，以及普通模型摘要；摘要若丢失信息，单独测量，不能把它当成无损整合。
3. 分离旧判断。比较保留旧模型结论与仅使用原始回答证据的独立判断；固定额外调用量和证据来源。
4. 分离流程动作。重新计算节点后，比较保留旧路径与撤销受影响依赖。不得把新追问获得的信息混入固定输入的机制结果。
5. 观察错误与误反转。既测试早期错误被纠正，也测试原判断正确时是否被错误推翻；没有新实质证据的提醒和不同时间段事件作为负对照。

不能任意打乱自然病史来制造标签不变的任务。仅对可以保持同一病例世界、事件时间与证据关系的披露顺序变体做配对，并审核有效性。

## 5. 复检应怎样实现与比较

hypothesis / proposed design：

复检输入为截至当前的源证据，保留否定、时间范围、排除条件、冲突和有效更正的来源。普通证据整合优先用可复核的无损方式；任何压缩、抽取或模型摘要都有单独成本和错误记录。

独立复检调用首先不输入旧节点结论。输出可保留、修订或延后；引用校验不能保证语义正确。变更状态后，按经审核的依赖规则更新分支；不把复检等同于重新向角色问同样问题。

初始触发候选是影响旧节点的新证据、同一时间范围的实质冲突、明确更正，或决策仍依赖未解决的必要条件。触发规则、阈值及限额仅在训练/开发阶段选择。模型自报信心不能默认视为可靠概率。

必须比较：

- 用户现有逐轮 JSON 单向树；
- 同证据多调用一次的普通复算；
- 截至当前的证据无损合并后在独立调用中重算；
- 普通摘要后的独立重算；
- 固定间隔或每轮复检，以及全部已知条件的全历史重算；
- 候选选择性复检；有实际新贡献时再考虑学习策略。

复算基线同样可以使用新版证据和正确的知识规则。不能通过保留错误旧标签、提供较差输入或减少它的访问权限将其弱化。

配对限制累计输入/输出 token、调用与延迟；相同调用次数不一定是相同成本。超预算、失败、合法延后和未恢复均纳入结果。固定回放验证通过后才进入受控交互，单独检验必要澄清和无必要重复。

## 6. 继续、补证据与放弃条件

| 维度 | 当前判断 |
|---|---|
| 科学价值 | 候选问题比格式修复更具体；尚需证明独立失效机制 |
| 新颖性 | 未成立；L05—L08 与树回退先行工作是强反对证据 |
| 可执行性 | 有用户提供的聚合结果，但原树、版本、许可和逐例日志尚未审核 |
| 评测可信度 | 可用固定前缀与成本匹配提高可信度；不能使用未来标签触发复检 |
| 医疗外推 | 只评价离线/模拟任务，不主张实际诊断效益 |

继续前先确认一个主要终点、主要对手、计算预算、数据分组和停止规则。可以预设成本约束下的任务质量为主结果，以正确恢复与误反转解释机制；不能看到结果后挑选最有利指标。

放弃或收缩：普通证据合并/全历史重算已经达到相同效果；改进完全由额外调用、信息或抽取器解释；没有稳定可复核的路径依赖错误；错误反转抵消恢复；只在人工错误注入上有效；最近工作方法已完整覆盖候选方案。
