## 3. 数据来源、分组和前缀

每份输入记录 `source_id`、来源类型、许可、是否允许外部 API、合成方法（如有）及冻结版本。`scholar` 只接收公开说明、合成或脱敏示例、汇总及安全日志，不接收可识别健康资料。

划分单位是独立源病例/来源组，不能将同病例的不同候选树、对话前缀、顺序变体、模板或修订副本放入不同划分。真实可用规模未确认，先审计组键；旧表的 132 项是候选树判断数，不能默认等于独立病例数。合成场景将同一底层事实表及改写家族作为一组。

开发集用于提示、预算点、选择规则和澄清上限；验证集用于冻结决策；测试集保持一次性封闭。少量数据不支持三份独立划分时，应在来源分组内使用明确的开发/封闭测试协议，报告限制，不能一边看测试错例一边调整提示再把结果称为验证性。

每个测试前缀只提供 \(H_{\le t}\)。原始事件时间与当前披露轮次是不同字段；保留迟到披露、明确否定、证据不足、跨时间事件、真实冲突和有效更正。不得把未来完整病例知识作为当前 gold 可判信息。重排只限经审定且事实与事件时间等价的披露变体，不能任意打乱自然病史后假设标签不变。

## 4. Gold 标注协议

### 4.1 原文证据与条件子要素

对每个前缀分别标注：条件/子要素 ID；可定位问题和回答片段；观察值；支持/反驳/不足；事件范围；仍缺的必要要素；冲突双方；有效更正及被更正项。允许多个等价见证组合，不强制模型复制唯一一句金标准措辞。

标注时区分三个层次：源对话明确表达了什么；这些内容能支持条件的哪一子要素；在当前已观察前缀下条件能否确定。最终病例标签不是当前前缀的证据标注，不用最终标签反向填补缺失事实。

关键要素由条件规则及标注者确定，不能按本方法自己选中的内容定义 gold。明确将反证、范围限定、阈值依据及未解决的必要项纳入，避免只评价正向症状召回。

增加“数值不同但位于同一阈值侧”和“证据不足回答仍含有原因/限定词”的样本，分别标注程序规则状态与源信息保真。最新见证即使保持规则状态，也可能丢掉这些重要信息；不能只用规则一致性作 gold。

### 4.2 质量控制

由具有相关领域能力的标注者独立标注并裁决分歧；人员资质和实际参与方式待确认，不在论文中虚构医生审核。开发阶段先处理歧义规则；建议在冻结测试集上双标具有代表性的来源组并报告逐字段一致性与争议比例。双标比例、裁决和可靠性指标须在看主结果前冻结。

显式保存 `unknown` 与 `conflicted`。如果标注者本身无法确定范围、有效更正或规则表达，不强制二值 gold；将其列为不确定/待裁决并说明排除政策。排除数量与原因透明，不能按模型是否答对决定。

## 5. 最小对照矩阵

### 5.1 A：提取器评测，不掺入选择收益

冻结模型、完整前缀、条件知识、采样与总预算，对比：

| 条件 | 输入与输出 | 主要问题 |
|---|---|---|
| A1：普通结构化抽取 | 相同条件列表与字段，输出原文定位的普通 JSON | 条件绑定提示是否本身带来收益 |
| A2：候选条件关联提取 | 相同条件列表、前缀与输出约束 | 是否减少极性/时间/缺项错误 |
| A3：人工 gold 提取 | 仅作可达到上限和定位失效的诊断对照 | 下游差距是抽取造成还是选择/判断造成 |

A1 必须也能看到规则并输出定位、未知与时间字段，不能故意用无条件摘要充当唯一抽取基线。抽取总成本相同；如果 A2 更多调用，给 A1 同预算的第二次提取/普通复算条件。A3 不作为可部署方法或主优越性对手。

### 5.2 B：同一候选账本上的选择器评测

各选择器得到同一接纳证据、同一条件和事件范围。分别在人工 gold 账本与同一个自动提取账本上运行，避免把提取质量混入选择效果。

| 条件 | 选择方式 |
|---|---|
| B1：按最近顺序 | 保留最近完整证据项，记录预算删项，不拆引用 |
| B2：条件相关检索 | 以同条件/子要素及范围检索，记录同预算规则包 |
| B3：普通摘要 | 相同账本做一般摘要，摘要成本计入；保留可审计来源关联 |
| B4：规则状态保持见证 | 保留所需子要素见证、冲突两侧及缺口；不可装入则返回不可行 |
| B5：完整账本 | 作为不受压缩的质量参考；成本完整报告 |

检索必须按开发集选择一个可执行强实现；仅弱关键词对照不足。最接近论文尚未完整复现时，不声称 B2 代表该论文算法。B1/B2 同样采用来源完整的原子项，不能通过截断引用将其弱化。

### 5.3 C：端到端固定前缀的强基线

| 条件 | 判断器获得的信息 |
|---|---|
| C1：完整原始历史 | 按原顺序的同一前缀、同知识 |
| C2：完整轮次 JSON | 相同问答与轮次/链接，不增加新事实 |
| C3：无损整合 | 同一前缀完整信息一次提供，保留事件时间与来源 |
| C4：普通任务摘要 | 同前缀摘要后判断；摘要损失与成本单列 |
| C5：强相关检索 | 条件相关问答检索后判断，完整规则成本计入 |
| C6：候选完整管线 | 条件提取、账本与见证后判断 |

`fact L01/L02 / 比较动机`：LLMs Get Lost In Multi-Turn Conversation 的 Concat 是单轮完整信息分点提供；已测试 Recap/Snowball 不能被解释为所有场景都解决多轮问题。定位见多轮账本 §3.3/§7.1。本实验的 C3 不是任意有损“一段摘要”。

先在所有条件完整输入都可装入的共同可行范围比较机制，再单独做预算压力曲线。完整历史超出指定上下文上限时报告不可行，不能默默截断成弱对照后仍命名“完整历史”。摘要和检索可以利用同一前缀做预处理，但包括它们全部访问与模型成本。

C 条件需共享同一判断模型、知识版本和判定输出。原型的规则状态输出与外部 LLM 条件判断分开评价；未接入疾病诊断器时，不把条件状态测试报告为病例诊断准确率。

### 5.4 D：必要机制消融与普通复算

只保留能回答机制的比较：去掉事件范围、允许最新值覆盖冲突、去掉缺口显式标识、用一般检索替代见证选择。它们属于故障诊断消融，不是安全默认设置；每次只变一个因素，共享候选证据和预算。

若评价修订，比较不修订、获批修订、每次证据变化都完整前缀重算；另给 JSON/摘要/检索及候选管线同预算的普通独立复算。复算使用截至当前的全部合法证据，不用旧错误标签限制基线。如果差异全被普通复算消除，应撤回独特修订机制的收益主张。

## 6. 指标与成本口径

### 6.1 主要终点候选

推荐把**成本约束下关键子要素遗漏率**作为固定前缀主终点候选：在 gold 明确存在、与目标条件相关的必要信息中，没有在传递给判断器的包里正确表示的比例。必须同时报告错误添加、极性/事件范围/值错误，避免靠大量复制内容降低遗漏率。主终点、关键集合和成本约束在运行测试前确认，不能事后选择最高提升的指标。

原文定位精确性与片段召回、语义映射正确率、unknown→false 错误、冲突双方保留、有效更正正确率、跨时间误修订、条件四态 macro-F1 为辅指标。缺项和延后的样本留在分母中，并报告覆盖率—错误率曲线。不同子要素可能有多项证据，统计分组与权重应防止长对话独占结果。

“状态保持率”仅衡量选中包与完整接纳账本的程序状态一致；gold 语义状态错误另报。需要同时查看抽取遗漏、接纳错误与选择遗漏，不能用第一项高分掩盖其他错误。

### 6.2 正确候选保护与改判

若接入经审核的诊断树，分别报告正确候选识别、错误候选排除、原始分子/分母、BA 与合法延后；不得只靠负类多获得总体准确率优势。保持原树预测和各复算结果，分正负候选记录错→对 \(n_{01}\)、对→错 \(n_{10}\)、正确保持及错误保持。

设正类允许下降幅度 \(\delta_+\) 为研究者/领域审核者提前确认的**研究接受阈值**。在负类改善同时报告正类变化及置信区间；若没有足够样本支持非劣效判断，应明确不能证明保持，不以“一项影响大”取消漏判分析。不把研究阈值声称为临床安全标准。

### 6.3 全链路成本

真实成本包括所有提取、摘要、检索辅助模型、判断、规划、复算、失败重试的输入/输出 token、调用次数、壁钟延迟和资源费用；同一模型固定价格/硬件口径并记录时间。缓存命中/未命中分别保存。调用次数相同不意味着成本相同。

初版 `pack_evidence` 默认的 UTF-8 字节只用于本地软件预算，不能换名为 token 节省或模型效率。论文 token 对照使用实际模型 tokenizer，计入完整消息封装、知识规则、引用与输出。端到端用累计 token 匹配预算，并补充每次判断的输入上限；不要一方仅限制最后包、另一方计算全部预处理。

冻结若干有任务意义的预算点，开发集确定，不靠给原始历史塞无关文本制造压力。预算不可行、API 失败、格式失败、修订拒绝、合法延后均记录，主表按预先冻结的全样本政策计入，不只评价成功调用。

## 7. 独立受控问询

只在固定前缀阶段验证后开展。各策略以同一底层事实表、同一初始信息、同模型/回答策略和最大总成本启动；事实表不是完整真实病例，也不允许回答器看到策略名称或参考答案。病例世界与事件范围可复核，允许不知道/不愿回答，不能默认未记录症状全部为否。

对照包括冻结准则问题顺序、普通 LLM 下一问、同意图范围去重、候选缺口覆盖规划。问题长度、每轮可问数量、澄清上限、回答噪声与停止规则相同。分别报告新获得的关键子要素、正确解决缺口、必要澄清、无必要重复、错误时间合并、拒答后追问及累计成本；仅少问不能证明更好。

另加入“仅针对尚未确定条件的简单覆盖”基线，它在 all/any/阈值条件已可判时停止追问剩余缺口。当前原型保留所有未解决子要素，因此不能靠打败固定全问序列宣称最优提问或最少问题。

候选规划分数是覆盖启发式，不是估计临床信息增益。模拟器偏差及可能偏爱结构化问题的倾向必须讨论；独立标注者盲看问题/回答是否解决预定缺口。自然真实访谈的效度和实际患者体验不由该模拟实验建立。

## 8. 统计与复现

主比较使用同来源组、同前缀的配对差异。在独立源组层面 bootstrap 置信区间，必要时按组做配对随机化检验；不把同病例的候选树或前缀当独立试次。预先登记一个主要对手、主终点与检验；多消融作为探索性或采用预定多重比较处理。

非确定模型至少记录独立运行/种子及实际可控随机项，重复次数由预算和开发集方差确定。没有独立重复就限定结论为单次冻结运行。效应、区间、失败数和绝对计数一起报告，不只报显著性。

每次保存代码 commit、知识/数据/分组版本、模型与解码参数、完整提示哈希、输入来源、提议与拒绝原因、获批修订、选择/省略 IDs、判断输入哈希、全部调用成本。gold 文件和实验器请求分开，以测试证明 gold 或未来证据没有进入请求。若真实模型版本无法钉住，记录 API 报告的版本及日期并列为限制。

## 9. 继续与停止门禁

| 门禁 | 通过所需证据 | 不通过时的动作 |
|---|---|---|
| 数据与知识许可 | 来源/授权明确，知识可审核，来源组可重建 | 不运行外部模型或确认性实验 |
| 可评测信息 | gold 子要素、范围、缺口与修订有可接受一致性 | 修订标注和规则，收缩主张 |
| 机制隔离 | 在同抽取/同证据或同选择器条件下仍有明确差异 | 定位为抽取提示或工程实现，不包装为独立算法 |
| 成本公平 | 全链路 token/调用/延迟可追溯；同成本强基线完成 | 不宣称效率或优越性 |
| 正类保持 | 按预设接受标准评价，错误反转透明 | 停止增加模块，优先查错；不能用排除率掩盖下降 |
| 稳健性与近邻 | 强对照可比，最近工作重叠审核，外部条件支持所作范围 | 仅保留限定实证/工具贡献，必要时放弃主创新 |

亚组只使用已合法提供、足以支持分析且不识别个人的类别（疾病模块、语言、来源、信息完整度等）。缺少人口属性/多病共存/分布迁移资料时直接报告缺口，不生成虚构公平性结论。所有离线效果限制在研究评价，不推断实际临床效用。
