## 3. 第一组对照：区分格式、轮次和状态的贡献

hypothesis / proposed protocol：使用相同对话回放、知识树、诊断模型及节点任务。先在所有输入都能容纳的条件下隔离表示因素，再单独测试上下文预算压力。逐轮文本本身、角色和真实对话顺序必须一致。

| 条件 | 模型可见的历史表示 | 目的 |
|---|---|---|
| T0 | 按顺序排列的文本，保留角色和消息边界，不显示轮次编号 | 文本表示对照 |
| T1 | JSON，保留同样的角色、原文和顺序，不显示轮次编号 | 与 T0 比较格式变化 |
| T2 | 与 T0 相同的文本，增加正确轮次编号 | 与 T0 比较轮次标识 |
| T3 | 与 T1 相同的 JSON，增加正确轮次编号 | 完成格式 × 轮次的四条件设计 |
| T4 | T3 + 用户已有的节点判断/诊断条件状态及实际更新规则 | 用户当前方法；新设计的核心对手 |
| T5 | 在 T4 基础上增加经实现审核确认尚缺失的证据绑定或修订机制 | 检验额外机制；不能重复计算已有功能 |

T0—T3 不提供历史诊断状态，且所有条件均保留真正的对话顺序。不能把“无轮次编号”做成打乱对话的另一项任务。

若原先的纯文本实现与 T0 不同，应增加一个忠实复现旧实现的条件，明确其其他差异。T4 必须审核用户实际实现，不能拿弱化的提示模仿替代。

优先分析：T1−T0、T2−T0、T3−T2、T3−T1，以及格式与轮次的交互；T4−T3 需计入状态生成成本。T5−T4 才用于检验新增机制的价值。

对所有可比条件使用一致的开发集调优额度和冻结规则。记录 tokenizer 下的实际长度、序列化方式、字段排列与提示哈希；自然长度结果和预算匹配结果分开。不得为了凑等长而加入只影响一方的干扰文本。

## 4. 第二组对照：诊断状态是否可靠更新

hypothesis / proposed protocol：先审核当前状态更新规则，再决定需要哪些新增组件。

- 如果原方法只更新当前节点：比较是否重算受影响旧节点及其依赖决策。
- 如果原方法已经会回退或重算：保留该机制作为强基线，评估证据定位、时间范围判断、修订有效性和成本；不能把回退本身重新声明为创新。
- 如果机制尚不清楚：先完成实现说明和复现，不假定其缺失，也不把 T5 的功能写成既定方案。

依据最新自述，首先审核“只向前走、可能不检查旧节点”的情况。对初始节点判断错误的来源病例，测量其后续状态与最终预测；自然出现的错误与人工注入的错误分开报告。固定回放用于在输入一致时隔离状态机制，不能证明系统在真实交互中一定会获得纠错所需的新证据。

建议覆盖：明确更正、同一条件的相互矛盾表述、另一个时间段的新事件，以及不应改变既有判断的普通补充。保留原方案的阴性对照和误反转指标。

“去重”和“纠错重评估”需分开：先利用已有原文重新计算旧节点，不必再次向角色提问；只有证据仍不足时才提出澄清问题。交互扩展应区分无信息增益的重复问题与有必要的澄清，不能把所有再次询问都记为坏重复。重复问题标签和必要性判据须提前定义并审核。

hypothesis：模型生成的旧节点判断可能影响后续判断。可探索性地加入“过时或错误旧状态”压力测试，检查新证据能否纠正它。人工注入错误的压力测试必须与自然错误分开报告；该设计不表示用户当前系统已被证实存在这种问题。

## 6. 指标、统计和失败判据

hypothesis / proposed protocol：

- 节点层：按来源病例先聚合节点判断正确率，或在标签定义支持时计算状态 macro-F1；无标签、弃答和解析失败均单列。
- 任务层：最终诊断标签 macro-F1、标签集合正确率与覆盖率，沿用原实验协议。
- 修订层：有效更正后的恢复率、恢复所需轮次、未恢复比例、错误反转率。
- 树流程层：早期错误节点后的下游错误比例、错误被纠正的比例、无必要重复提问率、必要澄清次数、总访谈轮数。需先冻结错误、依赖与提问必要性的标签定义。
- 证据层：关键证据遗漏、原文可追溯率、无依据状态更新、时间范围错误。
- 成本层：全部抽取、状态更新、记忆选择和诊断调用的输入/输出 token、延迟与失败次数。

使用相同来源病例的配对比较，保留同源对话、前缀和随机种子的簇结构。格式四条件的分析与 T5−T4 的主要验证分开；最终主预算、主比较、样本数和多重比较规则在查看测试结果之前确认。
