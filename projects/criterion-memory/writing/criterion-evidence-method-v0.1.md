## 1. 研究问题与范围

`hypothesis HE01`：在相同已观察对话、知识规则、判断模型和累计计算预算下，将信息显式绑定到条件的子要素，并保留足以重现这些子要素状态的原文见证，是否比完整 JSON、普通摘要及检索更少遗漏决定当前条件所需的信息？

这里的“关键信息”采用可标注的任务定义：它能够支持、反驳、澄清或更正当前目标条件的一个子要素，或者揭示该子要素仍缺证据。不是由模型自行打一个“重要性分数”后裁剪对话。本原型的输出是条件证据状态、可追溯信息包和下一步提问计划，不直接给个人输出疾病诊断。

候选方法包含三个可拆分的过程：模型提出带原文定位的证据；程序维护来源、时间范围、冲突与经批准的修订；程序在给定预算下选择条件见证，并对未解决子要素安排追问。研究贡献是否成立取决于受控实验，不能由组件数量或 JSON 格式证明。

`fact / 已核验相关工作`：PsyCoTalk 已报告 SCID-5-RV 的层级状态机和诊断上下文树（F02）；ProAI 已报告包括 back 动作的诊断准则树（F04）；Human-Centered Annotation 已报告证据选择、条件级分析和专家修订（F09）；DDO 已报告问询与分类的分工（L08）。这些事实的来源与定位见第 10 节。

`inference / 最强反对意见`：本方案可能只是已有树、条件抽取、可追溯引用和规则处理的工程组合。即便整体结果提高，也必须排除额外知识、更多模型调用、较强抽取提示和信息权限不同的解释。候选主线是“哪些任务关键要素在压缩或修订时被丢失，以及约束是否减少这种丢失”，而不是首次提出证据记忆或模块分工。

## 2. 条件与对话表示

`hypothesis / proposed implementation`：令截至轮次 \(t\) 的可见对话前缀为 \(H_{\le t}\)。每条回答显式链接到它回答的问题，来源片段以轮次标识及 Python Unicode 字符区间 \([s,e)\) 定位。字符区间不是 tokenizer 的 token 区间。

一个条件 \(c\) 包含子要素集合 \(F_c\)。每个子要素定义标识、布尔/数值/字符串类型、比较规则、目标值、事件范围 `scope_id` 和提问意图 `intent_id`。事件范围由知识与标注协议预先规定，不把“本周”和“过去一次事件”自动合并。原型支持 all、any 及 at_least 规则；仅在受审核的条件确实可用这些规则表达时使用。

证据提议写为

\[
e=(\mathrm{id},c,f,v,\omega,q^{\mathrm{span}},a^{\mathrm{span}},U),
\]

其中 \(f\) 为子要素，\(v\) 为提议的值，\(\omega\) 为事件范围，\(q^{\mathrm{span}}\)、\(a^{\mathrm{span}}\) 为原问题/回答片段，\(U\) 为提议替代的旧证据 ID。`null` 表示证据不足，不等于 `false`。同一回答可以支持多个条件，但每个映射都需要单独审核。

`depends_on` 仅记录派生缓存的失效依赖。它不代表两个诊断条件之间的临床前提关系。需要布尔组合的知识必须显式编码，不能从依赖图推断疾病标签。

## 3. 提取器提出候选，来源校验约束入账

`hypothesis / proposed implementation`：提取器只读取 \(H_{\le t}\) 和冻结条件定义，提出当前可见信息的证据映射。评测标注、最终标签、未来回答及预期输出不进入提取请求。接口允许注入模型传输实现；本地回放默认不要求网络调用。来源未明确授权外部 API 时，不能外发文本。

入账前的程序校验覆盖：严格字段/类型；条件与子要素存在；片段与原文完全对应；问题和回答角色正确、链接一致；证据在当前前缀内可见；数值有限；修订目标合法。校验失败记录原因并拒绝该项，不静默改写证据。

普通提取接口不提供旧证据 ID，要求 `supersedes=[]`，不能自动完成更正。修订由单独的研究者工作流提交并批准；自动识别更正与提议替代对象仍是后续扩展。临时提议 ID 使用可见前缀的命名空间；接纳生成新的前缀快照，不复制原全轨迹的未来资料。接纳时间可能晚于原引用轮次，不能把迟到提取倒填到过去。

**校验的保证范围仅是结构与来源一致性。** 一个真实存在的引用仍可能被模型错误解释；回答范围也可能与条件不符。提取器完全没有提出的关键事实不会被引文检查自动找回。因而分别评价定位正确性、语义映射正确性与抽取覆盖率，不能把“所有引用都存在”写成“事实可靠”。模型自报信心不用于把未知状态变成确定状态。

## 4. 保留不确定性与受控修订

`hypothesis / proposed implementation`：每个子要素具有 supported、refuted、unknown、conflicted 四态。支持/反驳由经过来源校验的提议值与子要素规则比较得到；没有值或没有可用证据时保留 unknown。同一事件范围内同时存在支持与反驳时保留 conflicted，不用最新轮次、引用长度或模型信心擅自选边。其他时间范围的证据不能自动替代当前范围的状态。

修订需要显式批准，且只能替代同一条件、子要素和事件范围下较早的活动证据。模型响应不能自行批准它提出的替代操作。批准轮次与接纳轮次单独记录，以两者较晚时刻为生效点。修订保留原记录并追加替代关系，历史前缀查询不会看到未来更正或未来批准。不同时间事件中的不同回答不是天然矛盾，更不是可互相覆盖的更正。

条件聚合采用保守规则：all 中一个已反驳的必要子要素足以反驳该条件；any 中一个已支持的子要素足以支持该条件；不能确定时保留未知/冲突。对至少 \(k\) 项成立的规则，令 \(n_s\) 为已支持项数、\(n_p\) 为仍可能成立的项数。仅在 \(n_s\ge k\) 时支持、\(n_p<k\) 时反驳，否则保留未解决状态，并暴露缺口及冲突。具体状态优先级需与实现测试及领域审核保持一致。

新的接纳证据或获批修订记录受影响条件与传递依赖 ID，并重算条件。初版没有树缓存或路径回退，依赖记录供后续适配器使用。这是派生状态维护，不等于旧诊断树已实现自动回退或临床正确纠错。

## 5. 条件见证选择与预算

`hypothesis / proposed implementation`：对于当前条件，将活动证据集记为 \(E_c(t)\)，程序聚合器记为 \(R_c\)。初版选择一个见证集 \(S_c(t)\subseteq E_c(t)\)，保留每个已解决子要素的必要支持/反驳见证，以及冲突中双方的见证；未解决子要素以显式缺口保留。完整问题/回答引用、事件范围及规则定义组成原子的判断包。可省略冗余证据，但省略 ID 必须记录。

见证保持的可测试要求为

\[
R_c(S_c(t))=R_c(E_c(t)),
\]

并单独检查所有子要素状态、事件范围、冲突两侧和缺口标识的一致性。仅比较条件末端标签不够：例如一个 all 条件因一项被反驳而结束，仍可能隐藏其余必要项的证据遗漏。初版因此保留所有已解决子要素的见证，可能并非最小包。

这个等式只相对于**已提出、校验并接纳的证据账本和冻结程序规则**成立。它不能证明源对话信息全部被提取，也不是医学上的充分证据定理。本稿称其为“规则状态保持的见证包”，暂不宣称全局最小、最优压缩或真正临床决策充分。

初版明确选择每个子要素、每种规则极性的最新见证，不搜索最小集合。相同阈值侧的不同数值、证据不足回答中的原因及范围外证据可能省略；应独立测量这些语义信息的保真，不能用程序状态相同掩盖它们丢失。

令 \(P_c\) 为规范序列化后的完整判断输入，则预算约束是 \(\operatorname{cost}(P_c)\le B\)，覆盖规则、元数据及所有保留引用，不只计证据正文。默认实现口径是 UTF-8 字节。只有注入目标模型的实际 tokenizer 后，才能报告模型 token 预算。字节缩短不自动等于计算成本降低。

若必需见证与规则包不能装入预算，返回不可行状态并延后判断，不能单删冲突一侧、截断关键引用或发送超预算输入。超预算率是方法结果的一部分；不得剔除这些样本后声称相同质量和更小上下文。

## 6. 提问记录与条件判断分离

`hypothesis / proposed implementation`：提问记录仅用于记录某个 `intent_id + scope_id` 已提问、已回答或被拒绝。它不能改变条件证据状态；“问过”不表示“条件成立”，也不表示回答已经提供了全部信息。判断包不包含去重标志、提问账本或旧模型结论，便于检查去重开关是否改变同一前缀的判断输入。

规划器合并同意图、同范围的未解决子要素，先按能够覆盖的未解决条件/子要素数排序，再考虑冲突，采用固定平局规则。已经回答但证据仍缺失时允许有上限的澄清；拒绝或达到上限时延后。不同事件范围不因文字类似而被去重。

该分数是**确定性覆盖启发式**，不是患者疾病后验、临床信息增益或最优提问策略。本原型没有估计诊断熵，也没有强化学习训练。真正的有效追问需由独立标注、受控访谈和必要/重复问题分析验证。

初版仍覆盖逻辑短路已确定条件中的剩余未知子要素，因此不是最少问题控制器。是否终止由外部树与冻结协议决定；需比较“已决条件停止提问”的简单覆盖基线。

## 7. 处理流程

`hypothesis / proposed implementation`：

~~~text
冻结知识版本与来源政策
对当前可见前缀提出证据（或回放外部提议）
校验原文片段、问答链接、范围与修订权限
仅将合格项加入追加式账本；保留拒绝原因
按获批修订与依赖失效关系重算条件状态
按完整输入预算构建当前条件的见证包
若见证包不可行则延后；否则提供可追溯状态与包
根据未解决子要素与独立提问记录生成下一步计划
记录输入哈希、选择/省略、调用成本与失败
~~~

整个过程要求前缀可见性与来源政策可检查。增加未来回答后可以形成新的状态，但不能倒改早先已保存的前缀结果。

本地 replay 的零模型调用只描述这次程序运行；已有提取成本与失败传输凭据另报。端到端成本必须聚合所有调用，未知 token 留空，不能记作零。

## 9. 需要实验回答的缺口

`hypothesis / proposed evaluation`：首先比较关键子要素遗漏、极性与时间范围错误、冲突/更正处理及条件状态一致性；再评价预算下的下游条件判断。提取器产生相同候选证据时比较不同选择器，选择器固定时比较不同提取方式，避免将两者收益混成一个故事。问询策略仅在独立受控访谈阶段评价。

失败条件包括：同成本普通 JSON/摘要/检索达到相同结果；选择改善只在人工完美抽取器下出现，现实提取遗漏仍主导；压缩增益来自非法删掉反证或更多延后；正确候选判断发生未接受的下降；同预算普通复算消除差异；近邻方法已完整覆盖候选机制。详见 [实验设计 v0.3](../05-experiment-design-evidence-extraction-v0.3.md)。
